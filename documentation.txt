1. PROJECT GENESIS & THE TRANSITION FROM STREAMLIT
--------------------------------------------------------------------------------
StatVision initially began as an exploratory data analysis tool prototyped with
Streamlit. While Streamlit allowed rapid proof-of-concept development, it quickly
exhibited architectural bottlenecks in a real-world exploratory environment:
  - Slow full-script re-runs on every user interaction (slider movement, clicks).
  - Heavy WebSocket overhead and persistent state serialization lag.
  - Restricted styling capabilities and lack of genuine layout control (rigid
    containers, clunky sticky sidebar workarounds).
  - High container memory footprint.

The Decision:
We completely retired Streamlit and re-architected StatVision into a blazing-fast,
lightweight, decoupled web platform built upon:
  - Backend: Standard Python (Flask 3.x + Gunicorn WSGI)
  - Data Processing: Pandas & NumPy (vectorized C-speed matrix math)
  - Frontend: Vanilla HTML5 & Modern CSS3 (zero bulky frontend frameworks)
  - Visualization: Native client-side Plotly.js (hardware-accelerated WebGL/SVG)


2. BACKEND ARCHITECTURE & STATISTICAL ENGINE (app.py)
--------------------------------------------------------------------------------
The backend serves as a high-performance compute engine exposing clean REST
endpoints rather than server-rendered UI:

A. Endpoints:
  - GET / : Serves the core mathematical canvas interface.
  - GET /api/sample/<name> : Loads bundled benchmark datasets (Iris Morphometrics,
    Hospitality Economics) instantly without disk reads.
  - POST /api/upload : Accepts arbitrary CSV/TSV/TXT datasets (up to 32MB),
    sanitizes inputs, extracts data vectors, and returns statistical metrics.
  - POST /api/export-moments : Streams a mathematically structured CSV containing
    all computed moments and quantile thresholds.

B. Computational Mechanics (process_dataframe):
  - Topology: Vector extraction of total observation rows (N), dimension count (p),
    numeric features, categorical factors, and missing entry count (Nulls).
  - Five-Number Summary & Moments:
      * Mean: \mu = E[X]
      * Sample Standard Deviation: \sigma
      * Standard Error: SE = \sigma / sqrt(N)
      * Quantiles: Min (x0), Q1 (25%), Median Q2 (50%), Q3 (75%), Max (x1)
  - Automated Inferences & Diagnostics:
      * Null Entry Scanner: Identifies columns with missing data.
      * Skewness Diagnostics (\gamma1): Evaluates feature asymmetry and flags
        positive/negative tails (|skew| > 1.0) recommending log transforms.
      * Pearson Correlation Matrix: Calculates cross-variable linear dependence:
        r = Cov(X, Y) / (\sigma_X * \sigma_Y) bounded in [-1, 1].
      * Matrix Protection: Bounds correlation computation to top 50 numeric features
        to guarantee instant calculation without freezing the CPU.


3. FRONTEND DESIGN SYSTEM & 3D MATHEMATICAL UNIVERSE
--------------------------------------------------------------------------------
The visual identity of StatVision was crafted to create an awe-inspiring, premium
data science experience:

A. 3D Floating Geometry & Mathematical Atmosphere:
  - A 3D isometric gyroscope core animated in pure CSS with 6 rotating polyhedral
    faces (pf-1 through pf-6).
  - Floating equations spanning differential equations, Gaussians, limits, and
    matrix notation (float3D_1, float3D_2, float3D_3).
  - Mathematical typography using Google Fonts 'Space Grotesk' for bold titles and
    'Fira Code' for monospace metrics, symbols, and formulas.

B. Glassmorphism & Color Systems:
  - Curated Light & Dark themes with automatic persistence via browser localStorage.
  - CSS variables (--primary-color, --stat-card-glass, --stat-card-border,
    --pill-bg, --shadow-color) utilizing backdrop-filter: blur(14px).
  - Instant theme switching without page reloads, triggering reactive re-coloring
    of all active Plotly charts.

C. Layout & Responsive Engineering:
  - Desktop View: A permanently fixed sidebar (position: fixed, 310px width) that
    never scrolls away, keeping data controls and ingestion always accessible.
  - Mobile & Tablet View: Fully responsive off-canvas drawer navigation toggled via
    a mobile top navigation bar with a smooth cubic-bezier slide animation.
  - Content Flow: Balanced grid systems (5-column metrics grid, 3-column landing
    cards, dual-column chart grids) with edge-to-edge alignment and generous spacing.


4. CLIENT-SIDE VISUALIZATIONS & INTERACTIVITY (app.js)
--------------------------------------------------------------------------------
Rendering charts in the browser via Plotly.js offloads visualization workloads from
the server directly to the client's GPU:
  - Probability Density & Empirical Histogram with dynamic overlays of Mean (\mu)
    and Median (Q2).
  - Quantile Outlier Boxplot displaying five-number summaries with jittered scatter.
  - Cross-Collinearity Correlation Heatmap featuring diverging Blue/Red gradients.
  - Bivariate Regression Scatter Plot with an on-the-fly Ordinary Least Squares (OLS)
    regression line calculation (slope, intercept, Pearson r, R^2 coefficient of
    determination).
  - Categorical Factor Projections with dynamic aggregations (Mean, Median, Sum,
    Std Dev) and configurable category caps.
  - Debounced window resize handler ensuring charts adjust seamlessly on window
    resizing or mobile orientation changes.


5. SECURITY HARDENING & DEFENSIVE PRACTICES
--------------------------------------------------------------------------------
A comprehensive security review was conducted and hardened directly into the code:
  - XSS Protection: Full HTML entity sanitization (html.escape in Python and
    escapeHtml() in JS) preventing Cross-Site Scripting via malicious column names
    or cell contents.
  - Secure File Ingestion: werkzeug.utils.secure_filename sanitization eliminating
    Path Traversal vulnerability vectors.
  - File Whitelisting: Strict validation limiting uploaded files to .csv, .tsv, .txt.
  - Denial of Service (DoS) Defense: Hard payload cap of 32MB and a 100,000 row
    read ceiling (nrows=100000) to prevent RAM exhaustion.
  - HTTP Security Headers: Automatic injection of:
      * X-Content-Type-Options: nosniff
      * X-Frame-Options: SAMEORIGIN
      * X-XSS-Protection: 1; mode=block
      * Referrer-Policy: strict-origin-when-cross-origin
  - Environment Isolation: Debug mode disabled by default in production.


6. CONTAINERIZATION & CI/CD PIPELINE
--------------------------------------------------------------------------------
A. Minimal Production Dockerfile:
  - Built on official python:3.10-slim.
  - Layer-cached dependency installation via requirements.txt.
  - Pre-configured production Gunicorn WSGI runtime on port 5000.

B. GitHub Actions Automated Pipeline (.github/workflows/docker-publish.yml):
  - Automatically triggered upon git push to the main branch.
  - Authenticates with Docker Hub using repository secrets (DOCKERHUB_USERNAME,
    DOCKERHUB_TOKEN).
  - Builds and pushes the image directly to ajaygangwar945/statvision:latest.
  - Enables one-command deployment worldwide:
      docker run -d -p 5000:5000 ajaygangwar945/statvision:latest

C. Cloud Hosting on Render:
  - Native Python Web Service deployment directly linked to the GitHub repository.
  - Build command: pip install -r requirements.txt
  - Start command: gunicorn app:app
  - Automatic zero-downtime continuous deployment on every git push.
